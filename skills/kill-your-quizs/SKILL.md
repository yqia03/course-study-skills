# Kill your QUIZS

目标是交出完整、正确、刚好满足要求的作业。每段文字、每项设计、每段代码和每个附件，都应对应题目要求或支撑答案所必需的依据。**删掉后仍能完整作答、检查答案并满足提交要求的内容，就删掉。** 内部验算可以充分，提交内容保持最少；用户明确要讲解或扩展时再增加。

## 作业目录与课程资料范围

- **作业工作与输出目录（`work_root`）：** 将用户指定的作业目录解析为绝对路径；只指定题面文件时，默认取题面所在目录。答案默认放在其 `submit/`，草稿、提取文本和运行产物放在其 `.study-work/` 或题目要求的内部位置。明确指定的其他输出位置单独遵从；多个输入目录不意味着可以把公共父目录当作输出目录。
- **课程资料搜索范围（`reference_roots`）：** 与作业目录分别确定，可是一个课程目录或多个讲义目录，仅用于读取相关教材、笔记、PPT、勘误、代码和数据。优先采用用户本次指定或会话中已经明确的范围；“只用此目录”等限制优先，不因资料不足自动扩大。
- 仅给作业目录时，先读题面，必要时查看其**直接父目录**的名称和一级结构。若题面或会话的课程信息、父目录名称及讲义布局能明确对应同一课程，可将该父目录作为只读资料范围并简短告知；例如 `CS6480/problem_set_4` 可查同课程的 `CS6480/Lecture8`。不继续向上探测，也不把桌面、主目录或混合多门课的目录当成整门课范围。无法判断时先用作业目录内资料，确需其他依据再询问参考位置。
- 读取权限不扩大写入范围。即使从 `Lecture8/textbook/` 查阅教材，答案仍在 `problem_set_4/submit/`；不得在父目录或讲义目录写提取文件、缓存、运行结果或更新教材。运行参考代码前检查其输出位置，必要时将所需代码和输入副本放入作业目录再运行。读写前解析 `..` 与符号链接，分别核对实际读取目标和写入目标。
- 先读本次题面、评分标准、模板和必要数据，再按 [教材复用](references/textbook-reuse.md) 在作业目录及课程资料范围内定位相关教材。可复用的教材作为优先知识入口，不重复提取整套课件；优先按题目主题查相关讲次，不把扩大搜索位置变成通读整门课。题目要求、课堂约束和原始数据仍以本次原件为准。
- 没有可用教材时直接查相关原资料；完成作业不要求先运行 `learning-notes` 或生成完整教材。仅在用户要求制作或更新教材时使用该 skill；两者可独立安装。

## 读题与定范围

- 在作业工作目录定位题面与必要输入，在已确定的课程资料范围内用 `rg --files` 和定向搜索查教材及相关来源；教材缺少的依据再按题号查对应课件、课堂代码和已有答案，按内容确认课程、讲次与题目的关系。
- 直接读取 Markdown、HTML、notebook 和纯文本；PDF 可用 `pdftotext -layout`。DOCX/DOC 要检查正文结构；含公式、图表或版面歧义时，转换或渲染页面核对，图片题面用视觉识别或 OCR。保留原始资料。
- 在内部逐题列清：要回答什么、指定方法、必要步骤或论据、精度与单位、提交格式及附件。以题面和评分标准为边界，不把常见报告章节自动算作要求。
- 使用对应课件的术语、记号、公式和算法，优先复用课堂代码。只有题目需要时才引入课程外方法。
- 题面、公式、数据或要求的冲突会影响答案时，先核对资料；仍不能确认就询问用户，并继续不受影响的部分。输出格式按题面及用户指示确定；两者都未指定时询问用户。

## 写最小完整答案

按原题号和小问顺序作答，每问只写所需结果和依据。详略取决于题目动词、分值和评分标准，不统一套报告结构，也不靠固定字数截断答案。

| 题目要求 | 提交内容 |
| --- | --- |
| 填空、选择、只写结果 | 结果、选项及必要单位；要求理由时才补理由 |
| 计算 | 必要公式、代入或关键中间量、结果；常规算术可合并 |
| 解释、比较 | 直接回答原因或指定比较维度，用必要事实支撑 |
| 推导、证明 | 前提、关键推导和结论，保留使论证成立的步骤 |
| 编程、实验、设计 | 指定功能、实验或设计项，以及题目要求的结果和说明 |

- 默认给一条符合课程要求的解法；题目要求多种方法、比较、讨论或边界分析时，完整覆盖这些要求。
- 需要设计时，只写要求的流程、结构、接口或关系；范围以完成本题为止。代码使用直白的变量、循环和必要函数，保持可读，不追求压缩行数。
- 仅实现题目要求的功能和保证正确性必需的处理。额外架构、通用封装、配置系统、命令行选项、日志、备用算法或附加实验，只有题目要求时才添加；遵守已有模板和接口。
- 存在 `#TODO` 或指定作答区时，只在对应区域补全，保留原题、现有代码和测试。若原有代码的 bug 阻止完成作业，只作必要修复，并在交付说明中指出改动位置和原因。
- 需要计算或核对时可以运行临时代码；题目不要求提交代码且答案不依赖代码文件时，不把验算脚本附进提交目录。实验使用用户指定环境或当前可用环境，记录真实运行结果。

## 朴素的学生写法

- 使用题目或用户要求的语言，以普通本科生掌握的课程词汇直接作答。句子围绕本题的量、条件和结果，少用抽象评价。
- 若有用户提供或本课程已有的答案样例，参考其用词、记号和详略；历史格式不能覆盖本次要求，也不能成为新增章节的理由。
- 通常题号下直接写答案；只有内容需要区分时才加短小标题。段落、公式、表格选最清楚的一种表达，同一结果写一次即可。
- 用具体关系代替铺垫和评价。例如，问“为什么二分查找是对数复杂度”，可写“每次排除一半元素，经过 k 次后剩 n/2^k 个，所以最多需要约 log₂n 次。”无需先介绍算法的重要性，再重复结论。
- 去掉题意复述、写作计划、常规定义科普、装饰性过渡和空泛收尾，不套“本文将”“值得注意的是”“综上所述”等开头结尾。题目要求的定义、背景或总结仍需保留。
- 代码注释只解释必要的意图或不直观的步骤，不逐行翻译代码；变量名沿用课程与模板习惯。
- 自然感来自具体、简短和符合课程水平，不靠故意写错、加入错别字、编造个人经历或虚构实验过程。数值、引用和运行结论必须有依据。

## 验证与交付

- 对照逐题要求检查漏答、方法、推导、数值、单位、精度和题号；运行所需代码与已有相关测试，检查图表和最终文件显示。未完成的验证如实说明。
- 完整性检查后做一次删减：逐项确认文字、设计、代码和附件的用途，删除不影响要求或正确性的部分。保留必要依据，不把证明或解释题裁成孤立结论。
- 独立小问或模块可以并行，默认最多 4 个子代理且不超过工具容量；给每个子代理明确题目、材料和交付范围，并传达上述最小答案标准。各自写独立草稿，主 agent 统一组装。复杂或仍有疑点的部分可交给独立 reviewer，修正具体问题后再交付，不把审查扩展成额外解法或报告。
- 最终文件放在用户或题面指定的输出目录，并核对上述写入边界；只指定文件名或未指定目录时，放在作业工作目录的 `submit/`。只放所需格式和必要附件，不额外生成 Markdown 副本、README、日志、空模板或内部检查记录；不删除用户已有文件。
- 仅在作业要求时填写身份字段，值取自用户本次提供的信息或明确指定的个人配置；缺少必填值时询问，不从示例、历史答案或 skill 中猜填。
- 交付回复简短给出文件链接、验证结论和可信度（高/中/低及简短依据）；有实质修正或待复核问题才提及。调度、验算、review 过程及可信度留在对话中，不写进作业正文。
