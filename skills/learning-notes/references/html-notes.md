# 统一 HTML 教材、公式与配图

交付 HTML 教材时阅读。优先生成能直接打开、易于携带的静态文档；教学正文不依赖展开面板、交互操作或运行服务器才能阅读。

## 使用同一套设计

默认采用本技能的 [页面模板](../assets/textbook.html)、[共享样式](../assets/textbook.css) 和 [交互脚本](../assets/textbook.js)：纸白背景、深墨正文、青绿强调，独立一栏的连贯阅读区。目录默认收起，以浮层打开，内部切换课程/本章目录；不另加常驻左右侧栏，不挤压正文。字体、间距、行宽及组件使用同一套设计变量。风格统一不等于内容结构机械一致。

遵循入口文件的目录边界：默认入口是 `<范围根目录>/textbook/index.html`，拆章和外部资源分别放在 `textbook/chapters/` 与 `textbook/assets/`，使用相对链接。保护原始资料；同名文件若是用户原有资料，另选范围内的不冲突位置并明确交付入口。用户明确指定输出位置时使用该位置。

写教学正文为 HTML 片段，保存在范围内的 `.study-work/`，用 [构建脚本](../scripts/build_textbook.py) 将模板、CSS 和正文组装成单文件，并自动生成目录。`--scope-root` 必填；默认输出到其中的 `textbook/index.html`。配合 [教材索引](textbook-handoff.md) 传入 `--catalog`：

```bash
python3 <skill-dir>/scripts/build_textbook.py \
  --scope-root "/课程/lecture5" \
  --body "/课程/lecture5/.study-work/chapter-body.html" \
  --title "Weighted sum（加权和）" \
  --subtitle "学习范围与目标的简短说明" \
  --course "课程名称" \
  --catalog "/课程/lecture5/.study-work/catalog.json"
```

`--output` 可指定范围内其他 HTML 路径。用户明确指定范围外输出时，把构建范围设为该授权输出目录，草稿和有记录的来源副本均放在其中；不能擅自把范围升至公共父目录。脚本不替代授权判断。

正文片段不包含 `html/head/body/h1/style/script/base`；页面总标题由脚本生成。章节用带唯一 `id` 的 `h2`，知识块用带唯一 `id` 的 `h3`，它们进入目录与搜索索引。`main`、`page-title` 及 `ln-` 前缀属于模板保留 ID。例题和基础补充内部小标题用 `h4`。资料须经理解、改写后放入片段，不能直接拼接原资料 HTML。脚本不负责事实核验或公式转换。

标题使用原资料英文名称加中文括注，中文解释放在相邻的 `.chapter-guide` 中。可在标题上添加有根据的别名，例如 `<h3 id="weighted-sum" data-aliases="WS|加权和">Weighted sum（加权和）</h3>`；仅收录资料采用或通行可靠的缩写，不为搜索臆造缩写。主标题、各级知识标题和目录均遵循英文优先，操作提示可用中文。

### 拆章教材与离线搜索

单文件模式会从全部 `h2/h3` 及其后正文构建索引，包含折叠基础和解析。课程目录显示章级标题，本章目录显示详细标题。拆成多个 HTML 时，用一次 `--book` 构建整份教材，而非独立构建各页：这样每页都带有本次教材的完整索引、课程目录及前后章链接。浏览器搜索索引内嵌，不通过 `fetch`、CDN 或服务器读取，支持本地离线打开。

在范围根目录的 `.study-work/` 中创建 JSON 清单，例如：

```json
{
  "course": "Week4 · Neural Networks",
  "pages": [
    {"path": "index.html", "title": "Weighted sum（加权和）", "subtitle": "怎样把不同输入合成一个分数？", "body": "part1.html"},
    {"path": "chapters/02.html", "title": "Decision threshold（判定阈值）", "body": "part2.html"}
  ]
}
```

`body` 相对清单所在位置，`path` 相对教材输出目录；默认输出到 `<范围根目录>/textbook/`，首个页面须为 `index.html`。清单只列本次已编写的教材页，不能扫描其他课程来扩大搜索范围。浏览器全文索引与供 agent 定向读取的 `textbook-index.json` 用途不同；后者不复制全文。

```bash
python3 <skill-dir>/scripts/build_textbook.py \
  --scope-root "<范围根目录绝对路径>" \
  --book "<范围根目录绝对路径>/.study-work/book.json" \
  --catalog "<范围根目录绝对路径>/.study-work/catalog.json"
```

`--output-dir` 可指定范围内的其他教材输出目录。全部片段及输出目标通过检查后再写入；输入片段、构建清单和所有输出路径必须实际位于范围内，符号链接不能越界。脚本允许更新有本技能生成标记的旧教材，拒绝覆盖其他已有文件。搜索优先匹配标题，其次别名和正文；点击结果跳到知识块，匹配折叠内容时展开相关补充。索引以知识块为单位，不以单句生成大量结果。禁用脚本时正文和 `details` 仍能阅读，并提供基础目录。

| 教学内容 | 共用组件 |
|---|---|
| 学习目标、必要基础 | `.learning-goals`，简洁列出本章能解决的问题 |
| 知识块评级 | `.importance` 内包含 `.rating`，数字、星级及理由均可读 |
| 引入问题 | `.lead-question`，紧接正文解释，避免空泛口号 |
| 完整示范 | `.worked-example` 与 `.callout-title`，展示思考和中间过程 |
| 概念澄清、易错点 | `.callout`；误解辨析用 `.callout.misconception` |
| 学生尝试 | `.checkpoint`；提示/答案可用 `details` 与 `.answer` |
| 就地基础补充 | `details.prerequisite`，不写 `open`，紧邻首次需要的正文解释 |
| 记忆线索 | `.memory-cue`，核心块末尾一句白话关系或判断依据 |
| 公式、表格、图 | `.math-display`、`.table-wrap`、`figure/figcaption` |
| 来源和章节过渡 | `.source`、`.chapter-bridge` |

例如，评级结构可以写为：

```html
<div class="importance">
  <span class="rating">★★★★★ · 5/5 核心基础</span>
  <span>理由：下一节的方法需要用到这里的计数原则。</span>
</div>
```

正文以正常段落为主；不要把每段都塞进卡片，或用不同装饰颜色暗示不同学科重要性。自绘图使用同一配色语义，原资料截图保留其真实样式。只有用户要求改主题时才整体调整设计变量，并对所有章节应用同样的改动。

多章文件使用上述清单共享目录和索引。没有 Python 时可手工组装相同模板、样式、脚本与索引；不能因此丢失已要求的交互或换主题。成品不保留模板变量、占位正文或制作日志；学习者看到的是教材。

## 文档与术语

- 使用完整 HTML 文档、UTF-8、`lang="zh-CN"` 及适合手机宽度的 viewport。主要正文为简体中文，留出舒适行距和适合长文阅读的行宽。
- 使用真实标题层级、可点击目录锚点和语义化段落。正文、例题、评级、图注和来源有清楚区分，评级同时显示数字与文字。核心讲解与完整示范直接展开；既有基础的详细补充、练习提示及答案使用默认收起的 `details`。基础块前的正文必须先给一句够用的说明。
- 专业术语在知识块标题和首次介绍时采用 `English term（中文释义）`，例如 `Standard deviation（标准差）`。首次使用缩写可写 `Central limit theorem（中心极限定理，CLT）`，此后保持统一。保留资料中的大小写和专有名称；资料只有中文时补充可靠的通行英文名称，无把握则注明待核实，不能生造英文术语。
- CSS 优先内嵌，图像和公式资源优先内嵌或静态预渲染。资源较大时采用教材目录内的相对路径资源目录并一起交付；来源显示路径相对范围根目录，实际链接要按所在 HTML 的层级计算，例如入口回链原资料可用 `../lecture.pdf`；不要使用只在制作机器上有效的绝对路径，或仅交付缺少资源的 HTML 文件。
- 引用内容中的 `<`、`>`、`&` 等按文本正确转义，避免代码示例或原资料片段意外变成页面标签。内部台账可以保留 Markdown；最终目录与覆盖表应是实际 HTML 内容。

基础补充示例：

```html
<p>把两个数量依次写成 [3, 1]，在这里称为 Vector（向量）。</p>
<details class="prerequisite">
  <summary>基础补充：Vector（向量）——为什么顺序不能换？</summary>
  <p>本例先放“中奖”的次数，再放陌生链接的个数。交换顺序后，每个位置代表的含义就变了。</p>
</details>
```

## 保留公式格式

- 区分行内公式与独立公式，完整保留原有符号、分数层级、上下标、括号、向量、矩阵、分段函数和推导对齐。解释文字放在公式前后，不挤进公式图片里。
- 根据可用环境采用可靠的数学排版方式，例如 MathML、静态预渲染的 SVG，或完整打包资源的 MathJax / KaTeX。没有特定库要求，也不要假定浏览器会自动渲染 LaTeX。
- 优先确保本地打开时也能正常阅读。若使用运行时渲染，验证字体、脚本和样式资源确实加载；仅引用外部 CDN 且没有可靠离线呈现的方案不作为默认交付。不能在渲染失败时只留下 `\frac`、`\(...\)` 等裸源码。
- 可选择与公式相称的可访问说明，例如 MathML 语义或 SVG 的文字替代，正文仍逐个解释必要符号。公式太宽时允许局部横向滚动，不用极小字号或裁切隐藏内容。
- 原式已核实、但难以准确转换成数学源码时，可使用清晰的原资料公式截图并附来源及符号解释。原式本身仍有疑点时，先核实再使用，不能借截图绕过可靠性判断，也不猜测 OCR 丢失的负号、指数或分母。截图是一种保留原式的方式，不能把所有公式和讲解都转成不可读的整页图片。

## 原图截取与自绘图

选择能帮助理解的图，不为每块知识强行配图。

| 情况 | 选择与要求 |
|---|---|
| 原资料的图准确、清楚且适合当前讲解 | 用截图、页面渲染或图像提取工具取得，保留坐标轴、图例、单位、箭头及理解所需的上下文 |
| 原图细节密集，局部足以讲清当前问题 | 截取相关区域；图注说明来自哪份资料、哪页及截取范围，不能截去会改变结论的条件 |
| 原图缺失或不适合入门，但现有事实足以作图 | 用 SVG、绘图工具或其他合适方式自绘；标为“教学示意图”或“依据所给数据绘制”，不能冒充原图复原 |
| 数据或关系不足以支持图形 | 保留缺口；不能臆造曲线形状、数值或实验结果来补齐图 |

- 流程、结构、几何与概念关系优先使用可清楚控制标签的矢量图。定量图依据真实数据绘制，坐标、比例、单位和图例必须正确；若示意图非按比例绘制，应明确说明。需要生成插画时使用环境中适用的图像工具，不能让装饰性插画替代精确关系图。
- 图像放在首次需要它的解释旁，用 `figure` / `figcaption` 或等效结构附来源和说明；提供替代文本。图内专业标签尽可能采用英文在前的双语形式。
- 原图中的文字不必强改成双语，以免损坏原意；在图注或相邻正文解释其中的重要英文标签。自绘图则使用与正文一致的术语、符号和配色含义。
- 正文带读者看图：先说明图展示什么，再指明关键部分及读图顺序，最后解释它如何支持当前知识。不能仅插入图片并写“如图所示”。
- 图像以实际可读尺寸显示，保留足够分辨率。带文字的宽图若缩到手机宽度后标签过小，用 `figure` 内的 `.figure-scroll` 包裹图像，添加 `tabindex="0"` 和明确的区域标签；它保持最低绘图宽度并只在图内横向滚动，必要时按图调整 `--figure-min-width`。图注提示可横向查看。多列表格可用 `.table-wrap.wide-table` 保持列宽。图像资源须随 HTML 可用，不能依赖聊天附件的临时地址。

## 成品检查

在可用浏览器或渲染工具中实际打开最终 HTML，检查代表性的长公式、复杂公式、原图、自绘图、来源链接和目录锚点；至少查看普通桌面宽度与较窄宽度下的布局。若文档有打印样式，也查看打印结果是否裁切图和公式。

检查初始目录、基础块和解析均收起。打开浮层前后正文位置和宽度不变；切换目录、点击链接、关闭按钮、点击外部及 Esc 可用，关闭不丢阅读位置，键盘焦点合理。试搜真实英文标题、可靠缩写、中文名和正文短语，核对排序、上下文及目标；拆章时验证另一页的结果可达，离线索引完整。打印时基础和答案应展开，返回阅读后恢复原状态。

核对英文术语在前、中文括注在后，正文以简体中文讲解；检查无缺失图像、数学源码裸露、字体加载失败、内容重叠或横向裁切。原图与自绘图的身份及来源应清楚。多页教材检查共享样式、前后章链接和总目录是否一致；检查实际交付的文件和资源，而非只看制作过程中的预览版本。

没有可用视觉检查工具时，完成能够进行的结构与资源检查，并如实说明未做浏览器视觉验证。最后向用户提供 HTML 文件入口；使用外部资源目录或多章文件时，同时提供包含全部依赖的完整包。
